# TRQP Assurance Hub v1.13.0 — Profile-Aware Compositional Assurance

Hub v1.13.0 makes ecosystem-profile assurance an executable, version-bound composition of independently authoritative evidence rather than a Hub-local conformance claim.

## Added

- reusable TRQP profile contract and version-bound requirement catalogue;
- Ayra TRQP Profile v0.6.0-draft as the first proving profile;
- bounded proposition/result model with `PASS`, `FAIL`, `INDETERMINATE`, `NOT_APPLICABLE`, and `NOT_IMPLEMENTED`;
- executable Ayra profile adapter, authority/discovery evidence handling, adversarial suite, and reproducible evidence bundle;
- candidate TRQP v3 compatibility analysis that does not treat downstream draft work as upstream authority;
- CTS profile-consumable conformance evidence ingestion;
- TSPP profile-consumable posture evidence ingestion;
- cross-source regression proving producer `FAIL`/non-current evidence cannot be overridden by Hub-local success.

## Evidence impact

The Hub can now preserve an evidence chain of:

```text
profile requirement
  -> assurance proposition
  -> producer/local observation
  -> captured evidence
  -> dimension result
  -> composed assurance conclusion
```

CTS remains authoritative for mapped core conformance/replay results. TSPP remains authoritative for mapped security/privacy posture results. Profile authorities remain authoritative for profile normative strength. Governance legitimacy remains external-evidence dependent.

## Compatibility candidate

This component release is prepared for the TRQP Stack 2026.3 — Banyan candidate tuple:

- Assurance Hub `v1.13.0`;
- TRQP Conformance Suite `v1.10.0`;
- TRQP-TSPP `v0.17.0`;
- TSMM `v0.24.0`;
- TIS `v0.15.0`.

The tuple is not a coordinated release until the merged-main Stack eligibility workflow succeeds and the required visible human release judgment accepts publication.

## Validation

Release preparation requires successful Hub quality, Pages, combined-assurance smoke, lifecycle recomposition, portfolio integration, profile-consumer tests, adversarial tests, and coordinated Stack eligibility against the frozen tuple.

## Adoption impact

Implementers can test a named profile while preserving the distinction between protocol conformance, posture evidence, profile policy, optional extensions, authority/discovery evidence, and governance legitimacy. Assessors and relying parties can inspect which producer owns each material observation instead of consuming an undifferentiated `compliant: true` assertion.

## Upgrade note

Existing profile-less TRQP assurance behavior remains available. Consumers adopting profile-aware assurance should select an exact profile/version, preserve producer lifecycle state, and treat profile/source revision changes as reassessment triggers rather than silently reusing historical conclusions.

## Non-claims

This release does not certify an Ayra registry, transfer Ayra authority to the Hub, redefine TRQP core semantics, or turn self-generated evidence into independent assurance.
